# Project Timeline

| Week | Stage | Tasks | Evidence |
| --- | --- | --- | --- |
| Week 1 | Problem investigation | Identify the issue with physical loyalty cards and explain why it matters. | Problem description, journal entry |
| Week 2 | Proposed solution | Explain how a PWA can solve the problem for customers and businesses. | Proposed solution, deliverables |
| Week 3 | Interface design | Create storyboard sketches for the home page, sign-up page and dashboard. | Storyboard screenshot and explanation |
| Week 4 | System design | Plan data flow, database entities, data dictionary and class structure. | DFD, ERD, data dictionary, class diagram |
| Week 5 | Implementation start | Set up the Flask application repository and begin building templates, routes and database code. | GitHub commits, repository notes |
| Week 6 | Core features | Build sign-up, login, dashboard, rewards, transaction history and staff/admin pages. | Code progress notes, screenshots |
| Week 7 | Testing | Test account creation, login, role protection, point updates, reward redemption and PWA files. | Test cases, test report |
| Week 8 | Refinement | Fix security, database, mobile layout and PWA issues found during testing. | Updated screenshots, reflection |
| Week 9 | Final portfolio | Check that all stages have evidence and write final reflection. | Complete portfolio |

## Timeline Reflection

The timeline helps keep the project organised because each stage creates evidence for the portfolio. The Flask application has already progressed through core implementation and testing, so the next priority is collecting final screenshots, real user feedback and Lighthouse evidence.
